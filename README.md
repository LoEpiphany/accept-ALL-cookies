# 万物归序（SnapBox）

《软件工程》课程项目 · 队伍：**接受所有小饼干** · 成员：魏心玥（LoEpiphany）、卢紫慧（luzihui1024）

面向个人与家庭场景的物品收纳、临期提醒与家居管理应用。支持拍照录入、物理空间映射、口语化模糊搜索与原生系统通知，目标是"给每件物品一个角落"。

- **在线体验**：https://wanwu.dns.navy/ （网页版，除拍照识别外不依赖网络）
- **客户端形态**：基于 Capacitor 8 封装的 Android 应用，可调用相机、文件、通知等原生能力
- **数据形态**：本地优先——业务数据存 `localStorage`，照片存 `IndexedDB`；仅拍照识别在用户主动触发时经服务端代理转发到用户自备的模型服务
- **开发方式**：原生 HTML5 / CSS3 / JavaScript，无前端框架、无构建步骤

---

## 一、核心功能

### 1. 录入与保质期
- **拍照识别**：调用兼容 OpenAI 协议的视觉模型。默认使用腾讯混元（hy-vision-2.0-instruct），请求经自建代理转发至腾讯 TokenHub；也可切换智谱 GLM-4V 与通义千问 VL，这两家走各自官方直连接口。未配置 Key 时退回手动填写，主流程不受影响。
- **双重保质期**：未开封到期日与"开封日期 + 开封后可存放天数"两条时间线并行，取较早者作为有效到期日。
- **保质期预设**：内置 228 条"关键词—天数—冷藏/冷冻修正"数据，输入名称即可推荐天数。

### 2. 查找与筛选
- **反向查找**：输入物品名，返回库存数量并推荐最可能的存放位置。
- **口语化搜索**：内置 151 条场景映射（SMART_MAP）、30 组同义词与 266 条中英品牌映射，可用"生病""吃的""冷"等日常说法检索。
- **组合筛选**：关键词、分类、状态（过期/临期/低库存/已用完/闲置）与四种排序。

### 3. 空间与交互
- **两级位置树**："房间—位置"结构（如"厨房 → 冰箱冷藏区"），支持新增、重命名、删除与"其他"兜底。
- **拖拽归位**：长按物品拖到其他房间或储物柜，另有批量整理模式。
- **原生提醒**：通过 Capacitor LocalNotifications 提供每日整理提醒与临期横幅通知，点击直达详情。

### 4. 数据与安全
- **存储分离**：文本与配置存 `localStorage`（键 `wanwu_v1`），照片经 Canvas 压缩后存 IndexedDB（库 `wanwu_photos`），物品只保留照片 key。
- **容量保护**：写入前检查体积，超过 4 MB 提示预警；存储不可用时按 `localStorage → sessionStorage → 内存` 三级降级。
- **软删除**：删除进入回收站保留 30 天，支持恢复或彻底删除。
- **导入导出**：JSON 备份与恢复（合并/覆盖）、CSV 导入导出、A4 打印/另存 PDF；导出时剔除模型 Key。

### 5. 游戏化与统计
- 每日签到积分、35 项成就、周报（新增/过期/临期/丢弃）、分类与位置分布、过期构成。

## 二、技术架构：本地优先 + 服务端代理

项目为单页应用（SPA）与混合开发（Hybrid）结合：界面与全部业务逻辑在 `www/index.html` 中，原生能力由 Capacitor 桥接，唯一的外部依赖是视觉识别。

### 1. 分层
- **视图层**：`render()` 总控 + 模板字符串渲染五个一级页面，交互统一由 `document` 事件代理按 `data-act` 分发（共 87 个动作）。
- **业务层**：`fuzzySearch`、`effectiveExpDate`、`expStatus`、`matchShelfLife`、`suggestLocation`、`mergeQuantities` 等纯函数。
- **数据层**：`Store`（文本存储与降级）、`PhotoDB`（IndexedDB 图片仓库）、`load()/save()`（120 ms 防抖写入）。
- **原生层**：Capacitor 8.6 的相机、文件系统、分享、本地通知、状态栏、Preferences 插件，以及 Android 返回键处理。

### 2. 拍照识别链路（唯一跨网络数据流）

```
照片 → Canvas 压缩（网页相册选图 384 px / 质量 0.5，原生与拍照入口 800 px / 质量 0.6）
     → POST https://wanwu.dns.navy/proxy
     → EdgeOne 函数 functions/proxy.js 转发 https://tokenhub.tencentmaas.com/v1/chat/completions
     → 解析 JSON 并回填表单（30 秒超时；失败提示手动填写并保留照片）
```

代理只做请求转发、Key 透传（`Authorization` 头）与 CORS 处理，不存储任何业务数据。识别结果的落库必须经过用户确认，模型不会直接写入数据。

### 3. 本地数据
- 文字、设置、统计：`localStorage`（`wanwu_v1`），含 v9 数据迁移标记。
- 图片：IndexedDB（`wanwu_photos`），旧版 base64 图片按需迁移。
- 分享：基于 URL 哈希的只读视图，最多 60 条，不含价格。

## 三、目录结构

```text
accept-ALL-cookies/
├─ README.md                  # 本说明
├─ www/
│  └─ index.html              # 运行时单文件：HTML + CSS + JS + 内置数据（9758 行，约 510 KiB）
├─ functions/
│  └─ proxy.js                # EdgeOne 函数：转发视觉识别请求、处理 CORS
├─ capacitor.config.json      # appId com.whereis.app，webDir=www，通知小图标 ic_stat_wanwu
├─ package.json               # Capacitor 8.6 与相机/文件/分享/通知/Preferences 插件
├─ edgeone.json               # 静态站点与函数部署配置
├─ assets/                    # 图标与启动图源文件
├─ android/                   # Android 原生工程（minSdk 24 / compileSdk 36 / targetSdk 36）
└─ 万物归序*.html             # 22 个按日期命名的过程快照（过程版本，非最终交付）
```

> `node_modules/`、Gradle 构建缓存等不纳入交付压缩包；正式运行时文件只有 `www/index.html`。

## 四、运行与打包

### 1. 网页版
无需构建，直接托管 `www/` 目录即可；本地预览：

```bash
npx serve www
```

也可直接双击 `www/index.html` 离线打开，除拍照识别外功能完整。

### 2. Android 版
环境要求：Node.js、JDK 17、Android Studio。

```bash
npm install
npx cap sync android
npx cap open android      # 在 Android Studio 中编译、安装
```

### 3. 服务端代理（可选）
若部署到 EdgeOne，将 `functions/proxy.js` 一并发布，并把前端识别端点指向 `/proxy`；如使用其他平台，替换为等价的转发函数即可。

## 五、数据与隐私

- 业务数据与照片默认只保存在本机浏览器或应用的存储空间中，不上传、不注册账号。
- 拍照识别是**可选增强**：只有用户主动点击拍摄/选图并已配置 Key 时，压缩后的图片才会发往用户指定的模型服务；关闭或未配置 Key 时应用完全离线。
- 服务端代理只转发请求与鉴权头，不落库、不记录图片内容。
- 导出 JSON 会移除模型 Key；分享页只读且限制条数。
- 当前版本未提供独立隐私政策页面，正式发布前需补齐。

---

## 六、已知限制

- 无云同步与多人实时协作，换机需手动导出导入。
- 列表为分页 + 全量重绘（每页 60 条），物品上千件时可能出现卡顿，虚拟列表尚未实现。
- 搜索为布尔过滤，颜色词与场景词存在过度匹配问题（详见项目报告 4.3 节）。
- AI 识别依赖网络、第三方服务与用户自备 Key，弱网或运营商差异会影响体验。
- 测试以脚本与快照对比为主，尚未接入持续集成。
